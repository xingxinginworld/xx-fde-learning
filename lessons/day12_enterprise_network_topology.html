📖 二、核心讲解

是什么：政企网络的 5 层典型部署

你在公有云上部过服务对不对？你从阿里云买台 ECS，绑个公网 IP，配个安全组，就能对外提供服务了。政企机房完全不是这个玩法。政企网络是"层层隔离、逐级审批"的思路，一个公司内部可能同时存在 5 个物理或逻辑隔离的网络层。

🌐 政企网络典型 5 层拓扑（自上而下）
Layer 1 · 互联网 公有云资源 · 外部 SaaS · 公网 API（阿里云百炼、OpenAI、GitHub）
│ 🔥 边界防火墙 · NAT 网关 │
Layer 2 · DMZ 非军事区 对外服务网关 · 反向代理 · 邮件网关 · 面向公众的 Web 服务
│ 🔥 内网防火墙 │
Layer 3 · 办公内网 员工电脑 · 办公 OA/邮件/IM · 开发测试环境 · 通常有代理出网能力
│ 🔥 生产防火墙 · 堡垒机 │
Layer 4 · 生产内网 核心业务系统 · 数据库 · 中台服务 · 通常无外网出口
│ 🔥 隔离网关（可能物理隔离） │
Layer 5 · 隔离网 / 涉密网 涉密业务 · 国密加密 · 物理隔离 · 通常 AI 上不了
层谁能进能出网吗AI 服务能放这层吗
L1 互联网所有人本身就是放外面：客户不同意，数据不敢出
L2 DMZ外部 + 内部（有限）受控出网✅ 常见：AI 网关放这里做代理转发
L3 办公网员工 + 驻场有代理可出✅ 常见：开发测试环境放这里
L4 生产内网严格审批 + 堡垒机❌ 默认不能✅ 最常见：正式服务放这里，需白名单出网
L5 隔离网持证人员 + 物理进入❌ 物理隔离❌ 不能：AI 通常上不了

反直觉的地方：客户嘴上一个"内网"，其实可能是 L3 / L4 / L5 中的任何一个。你不问清楚，可能把服务部到 L3 结果客户要求 L4，白干一遍。

□ □ □ 政企 5 层网络口诀 □ □ □
互 · D · 办 · 产 · 隔
层层隔离，逐级审批 · 5 层每一层都有一道防火墙

为什么：驻场 FDE 的三个大坑

🚨 坑 1 · 以为客户"内网"是一个网

客户运维说"你把服务部到我们内网"，你就以为是"一个网"。等你部好了发现——服务在办公网（L3），但客户要接的业务系统在生产网（L4），中间还有一道防火墙。你的服务调不到业务系统，业务系统也调不到你。

正确姿势：拿到"内网"两个字先追问："是办公网还是生产网？跟我要对接的业务系统在同一个网段吗？"——一句话能救你 3 天时间。

🚨 坑 2 · 把办公开发环境当客户机房环境

你在某公司办公室调好了 Demo，用的是某公司办公网——能连外网、能装 pip 包、能访问 GitHub。你到了客户机房，插上网线，一样的代码连 pip install 都跑不通。

为什么？客户机房大概率是 L4 生产网，默认不能出外网。你办公室能连 pypi.org，客户机房连 DNS 都解析不了 pypi.org。

正确姿势：Demo 阶段就要问客户能不能出网、要不要走内网 pip 镜像、要不要提前打好 Docker 离线包。能连外网的环境 ≠ 客户生产网环境——这是驻场 FDE 最容易翻船的地方。

🚨 坑 3 · 忽略堡垒机（跳板机）的存在

你想 SSH 到生产网服务器上装东西——直接 ssh admin@10.100.x.x？拒。政企生产网基本都有堡垒机（也叫跳板机、运维审计系统）——你要通过堡垒机中转才能操作生产网服务器，堡垒机会全程录像、审计每一条命令、限制部分高危操作。

正确姿势：你需要客户给你开堡垒机账号 + 授权可访问的目标机器清单 + 授权可用的操作类型（SSH / RDP / SFTP）。这三样任何一个没到位你都进不去。堡垒机不是网络设备，是运维流程。

🧭 PM 行动指南：进客户机房前必问的 5 件事

Q1 · 网络层次：你们目前几层网络？分别是干啥的？（哪怕客户答"就一个内网"你也要追问 DMZ、办公、生产是分开的吗）

Q2 · 我们的位置：AI 服务准备放哪一层？（DMZ / 办公 / 生产）

Q3 · 上下游位置：我们要对接的业务系统 / 数据库 / 中台在哪一层？跟我们同网段吗？

Q4 · 出网能力：那一层能连互联网吗？能出的话走什么代理？不能出的话有没有内网镜像？

Q5 · 堡垒机：需要通过堡垒机吗？给我们开账号需要走什么流程？多久能开好？

这 5 个问题在第一次跟客户运维见面就要问清，越晚问代价越大。

怎么用：三种典型 AI 部署位置的取舍

部署位置典型场景优势约束
纯 DMZ 部署面向公众的 AI 客服 / 政务问答接入方便、出网灵活敏感数据不能进 DMZ，功能受限
DMZ 网关 + 生产网服务员工 AI 助手 / 内部知识问答安全性高、能对接业务系统需要打通两层防火墙 + 白名单
纯生产网离线部署数据涉密的 AI 分析 / 涉核心业务数据不出网、合规最强要私有部署大模型，成本高
混合部署大部分政企 AI 项目现状灵活取舍复杂度高，网络架构要画清

📓 复盘一句话

AI 项目在政企落地本质上是"在多层网络之间打通合规的通道"——每一道防火墙都要有白名单，每一个网段跳转都要有代理。

🧪 案例 B · 某商业银行客户拓扑（自己练）

拓扑描述：某商业银行 6 层网络——互联网 / DMZ / 办公网 / 数据脱敏区 / 核心业务网 / 涉密网。数据脱敏区是银行特有的，所有从核心业务网出到办公网/DMZ 的数据都要经过脱敏区做敏感字段脱敏（客户身份证、手机号、账号）。堡垒机在办公网到核心业务网之间。

问题：如果客户要求做一个"员工智能助手"回答业务政策类问题（不涉及客户隐私数据），你会建议部在哪一层？为什么？

查看参考答案

推荐：部在办公网（L3）为主 + DMZ 放 AI 网关。

理由 3 条：

  1. 业务政策类问题不涉及客户 PII，不用进核心业务网，避免触碰数据脱敏区的复杂合规
  2. 员工都在办公网工作，服务放办公网响应最快，跳的防火墙最少
  3. 调用 LLM 的出网走 DMZ 的 AI 网关，符合银行"所有外部出网必经审计"的常规要求

如果客户坚持要放核心业务网？提三条反问："是要对接客户数据吗？如果不对接，放核心业务网收益是什么？维护成本你们能承担吗？"——用反问帮客户想清楚。

面试金句："AI 服务部署位置不是越靠内越安全——越靠内维护成本越高、迭代越慢。要以业务数据敏感度反推部署位置，不是以'客户觉得安全'反推。"

🧪 案例 C · Bug case——Demo 上线后调不到 LLM API（自己练）

现象：你在客户生产网（L4）部署了 AI 服务，代码在办公室调通了，到客户环境启动后调用阿里云百炼 API 报错：Connection timed out。日志里 DNS 解析成功、但 TCP 连接不上。请给出 3 种可能的原因和排查方向。

查看参考答案

可能原因 3 种（按可能性排序）：

  1. 白名单没申请——生产网默认所有出网请求都被防火墙 drop，即使 DNS 解析出 IP 也连不上 443。排查：telnet dashscope.aliyuncs.com 443 看能不能通
  2. 生产网无外网出口，需要走代理——很多客户生产网要经 DMZ 的正向代理才能出网，你的代码没配 HTTP_PROXY / HTTPS_PROXY。排查：问客户运维要代理地址，在环境变量或 SDK 里配上
  3. DNS 解析被劫持到内网 IP——政企内网 DNS 有时会把外部域名解析到内部服务的一个"代理镜像"，但代理没配好导致连不上。排查：nslookup dashscope.aliyuncs.com 对比办公网和生产网的解析结果

验证顺序：先 ping 看网络通不通 → nslookup 看 DNS → telnet host port 看端口 → curl -v https://xxx 看完整请求。四把梯子上去，每一层出问题都能定位。

驻场经验：这种 case 8 成是 ①+② 组合——既没申请白名单也没配代理。所以 Day 13 我们要重点讲怎么申请。

📝 五、5 题小测验

建议先自己想 20 秒再点开答案。错项解析比正确答案更值钱。

Q1 · 客户说"把 AI 服务部到我们内网"，你的第一反应最该是？
  • A. 好的，我立刻安排把 Docker 镜像准备好
  • B. 追问一句"是办公网还是生产网？跟要对接的业务系统同网段吗？"
  • C. 让开发同学去部署，我不参与技术细节
  • D. 先跟客户申请 VPN，我自己在家远程部
✅ 答案：B

"内网"是模糊词，政企内部至少有 3-4 个网段，各自约束差别巨大。不问清楚"哪层内网"就动手，是驻场 FDE 最常见的翻车姿势。

❌ 错项解析

A 是典型的"客户说啥我做啥"陷阱——部错了层要推倒重来。C 是撂挑子——FDE 的核心价值就是搞清楚这些"边界不清楚的问题"。D 在政企场景基本不可行——生产网大多数客户不给外包发 VPN，你必须现场部。

Q2 · 关于堡垒机（跳板机），下面说法正确的是？
  • A. 堡垒机是一台服务器，可以直接跳过它 ssh 到目标机器
  • B. 堡垒机是运维审计通道，你必须通过它才能访问生产网服务器，且全程录像
  • C. 只有开发才需要用堡垒机，PM/FDE 不用
  • D. 堡垒机只是名字好听，本质就是个 VPN 服务器
✅ 答案：B

堡垒机是运维审计系统，核心作用是"所有生产网操作都必经这里 + 全程录像 + 高危命令拦截"。它不是网络设备是运维流程，能不能用取决于客户给你开不开账号和授权。

❌ 错项解析

A 说"可以跳过"是最危险的想法——政企生产网防火墙已经封了直连 SSH，你根本连不到目标机器。C 是身份错觉——FDE 也要登录服务器改配置、看日志、部署，同样需要堡垒机账号。D 混淆了堡垒机和 VPN——VPN 解决"能不能进内网"，堡垒机解决"进了内网后怎么管你"。

Q3 · 政企 5 层网络，AI 服务最常见的部署位置是？
  • A. L1 互联网（放阿里云上，客户直接调）
  • B. L2 DMZ（所有 AI 服务放 DMZ 里）
  • C. L4 生产内网 + L2 DMZ 出网代理（80% 政企内部 AI 项目的架构）
  • D. L5 涉密网（越涉密越安全）
✅ 答案：C

企业内部 AI 助手（80% 场景）的典型架构就是"服务在生产网 + 通过 DMZ 代理调用外部 LLM"。这个架构平衡了 数据安全（在生产网）+ 能调外部模型（走 DMZ）+ 客户可管控（有审计网关）。

❌ 错项解析

A 客户不会同意把数据发到互联网直接调——即使调外部 API，请求也必须从内网发出，不能让员工直连互联网。B 把所有 AI 服务放 DMZ 会导致敏感数据进 DMZ 违反安全规范。D 涉密网法规通常禁止 AI 服务，越涉密不代表越应该放——AI 上涉密网基本走不通。

Q4 · 你的服务在客户生产网启动后调阿里云百炼 API 报 timeout，最先该查什么？
  • A. 换个更快的模型，可能是模型太慢了
  • B. 用 telnet / curl 测试生产网到目标域名的端口通不通
  • C. 重启服务器
  • D. 找开发同学，说代码有 bug
✅ 答案：B

timeout 大概率是网络问题——白名单没开或代理没配。telnet host 443 或 curl -v 是政企驻场的第一把梯子，几秒就能判断是网络问题还是应用问题。

❌ 错项解析

A 换模型是最不靠谱的猜测——都 timeout 了根本没连上模型，换啥都白搭。C 重启服务器是运维老套路——网络问题不会重启就好。D 甩锅给开发是最糟的——同一份代码在办公室能跑说明代码没问题，问题在环境。

Q5 · 综合题：客户是一家省级国税局，要做智能税务问答，你会怎么规划部署方案？

给出你的部署位置建议 + 3 个进机房必问问题。

✅ 参考答案：分层部署 + 前期先摸清网络地形

推荐架构：

  • L4 生产网：AI 服务集群（应用后端 + 向量库 + 知识库）
  • L2 DMZ：AI 出网代理网关（做审计和过滤）
  • L1 互联网：LLM API（阿里云百炼或类似，走白名单）
  • 如果客户要求"数据不出境不出机房"——升级到"生产网私有部署开源大模型（如 Qwen 私有化）"

进机房必问 3 件事（收敛版）：

  1. "税务系统数据是否涉密？我们准备接的知识库敏感级别是啥？"——决定要不要私有部署
  2. "生产网能出外网调用外部 LLM 吗？如果能，走什么代理和白名单流程？"——决定架构
  3. "我们操作生产网服务器要通过什么？堡垒机账号怎么开？开好需要几天？"——决定驻场安排

面试金句："税务这种客户，我不会一上来讲模型选型，我会先花 3 天摸清网络拓扑和合规要求。网络地形决定架构上限，模型只决定效果下限。"

💼 六、面试金句预埋

网络拓扑意识 "做政企 AI 驻场，第一周我不写代码——我画图。把客户的 5 层网络画清楚 · 每一层放啥业务 · 每道防火墙什么规则 · 堡垒机怎么走——这张图画完，后面所有部署问题都是照着图对答案。不画图就动手，是驻场翻船的头号原因。"
部署位置决定架构 "AI 服务部署位置不是技术选型的结果，是反过来决定技术选型的因。放生产网要考虑私有化能力、放 DMZ 要考虑数据脱敏、要出网就要设计代理网关。先定位置再选栈是政企场景铁律。"
驻场敏感度 "客户嘴上说'内网'，我心里立刻问三个字'哪一层'。办公网 / 生产网 / 涉密网是三个截然不同的世界。这种敏感度是驻场老兵和新人最大的分野——新人听到'内网'就点头，老兵听到就追问。"

📓 心得笔记

⚠️ 今天最反直觉的 3 件事

1. 客户"内网"不是一个网——至少是 3-4 个网段，中间隔着好几道防火墙。（听到"内网"永远要追问哪一层。）

2. 办公室能连外网 ≠ 客户生产网能连外网——你的 Demo 到客户机房不一定能启动。（提前问出网能力和代理配置。）

3. 越涉密不代表越应该放涉密网——AI 上涉密网通常法规禁止。（部署位置以业务数据敏感度反推，别以"感觉安全"反推。）

🎯 老 PM 转 FDE 的思维切换

你在某公司做过那么多某单位项目，堡垒机、白名单这些词你听过一百遍——但你听过不代表你说得清。以前是客户运维告诉你怎么办；现在做 FDE，你要能主动看图、主动追问、主动画部署架构。这个跨度就是从"执行者"到"设计者"的跨度。你的驻场经验是天然优势，缺的只是把这些零散的听说，串成一张系统的地图。今天这张 5 层地图就是那根线。
