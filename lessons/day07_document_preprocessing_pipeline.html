环节干什么做不好会怎样
① 读取把 PDF / Word / Excel / 图片解析成文本，保留结构（标题、表格、列表）表格变乱码、图片全丢、公式变问号，后面检索答不上专业问题
② 清洗去页眉页脚、去水印、修 OCR 错字、合并跨页段落、去多余空白脏数据被嵌入向量，检索"招标日期"结果检出一堆页眉
③ 分块把长文档切成 200-500 字的语义片段，同一意思不切开该合的段被切散、该分的段挤一起，Top-K 检出来全是半截话
④ 存储每个分块附上元数据（来源、页码、章节、时间）后入库后期没法按时间/文号过滤，不能追溯出处，客户问"哪份文件说的"你答不上
□ □ □ 文档流水线口诀 □ □ □
读 · 清 · 切 · 存
四步一步都不能省 · 后面 RAG 的天花板就在这

为什么：PM 视角下的三个大坑

🚨 坑 1 · 直接把 PDF 丢给 LLM（表格/图片/公式全丢）

最经典的错误姿势——用 PyPDF2.extract_text() 一把梭，然后惊讶为什么模型答不出"招标金额"。

原因：PyPDF2 只能拿到文本流，表格里的"投标保证金 500,000 元"可能变成 "投标保证金500,000元" 混在正文里，也可能直接被跳过。图片格式的公章、盖章页、纯图 PDF 全部丢失。扫描版 PDF 更惨，一个字都读不出来。

正确姿势：拿到 PDF 先分类——文本 PDF 用 pdfplumber（表格保留好）+ unstructured（结构解析强）；扫描版 PDF 走 OCR（PaddleOCR 或阿里云 OCR）。永远不要用 PyPDF2 处理带表格的文件。

🚨 坑 2 · 一刀切固定分块（该合的切开，该分的挤一起）

新手最爱写 text[i:i+500] 每 500 字切一段。结果："本项目投标截止时间为 2024 年 12 月 15 日" 这句话可能被切成 "本项目投标截止时" 和 "间为 2024 年 12 月 15 日" 两块——检索"截止时间"的时候，两块都不完整，都答不上。

更糟的是表格：一张 8 行的报价表被从中间切开，Top-K 检出上半段没金额、下半段没项目名，LLM 编都编不圆。

正确姿势：优先按 结构切（章节、条款、表格整体保留），实在长再按 语义切（句号/段落边界优先），最后才是固定长度兜底。分块之间保留 10-20% 重叠。

🚨 坑 3 · 不留元数据（后期没法过滤/排序/追溯）

只把纯文本切好扔进向量库，是我见过 80% 政企 RAG 项目的通病。上线三个月后客户问："这段回答是哪份文件的第几页说的？"——你答不上。客户问："只查 2024 年之后的政策文件"——你做不到。

这时候补元数据？要重新跑一遍全流水线，历史向量全部作废。

正确姿势：第一版就要把元数据字段设计好——来源文件名、页码、章节标题层级、发布日期、文档类型。这是政企场景的合规硬要求，不是可选项。

🧭 PM 行动指南：预处理质量校验 4 关

关 1 · 可读性：随机抽 5 个分块，人眼能看懂在说什么吗？还是一堆乱码/半句话？

关 2 · 结构保留：原文的表格、章节标题、编号列表，在分块里还认得出来吗？

关 3 · 分块完整：核心事实（金额、日期、人名）有没有被从中间切断？

关 4 · 元数据齐全：每个分块能不能回答"哪份文档 / 哪一页 / 哪个章节 / 什么时候发的"？

四关都过再交给 embedding。任意一关不过，回炉重做，比调 Top-K 划算 10 倍。

⚠️ Excel 的隐藏坑：不要把整张表灌进 LLM

见过太多同学把 df.to_string() 结果直接塞进 prompt——一张 200 行 8 列的表格，输出一坨对齐困难的伪表格，LLM 读起来跟看天书一样。

正确姿势：把每一行（或几行）转成一句自然语言描述。例如"2024 年第 3 季度，华东区销售额 830 万，环比增长 12%，负责人张伟"。这种句子 embedding 之后检索效果高一个数量级。

分块策略：3 种主流选择

策略怎么切适用场景
Fixed 固定分块按字数或 token 数硬切，如每 300 tokens + 50 重叠纯文本、无结构的语料（对话记录、爬虫抓的网页）
Semantic 语义分块按句号、段落、语义相似度切，保证一块内话题一致文章、报告、政策解读——结构不强但段落清晰
Document-aware 结构化分块沿文档天然结构切：章节、条款、表格整体、列表整体合同、招标文件、法规、SOP——结构强、条款独立
□ □ □ 分块策略选择口诀 □ □ □
有结构走结构 · 无结构走语义 · 都不行才 Fixed
政企场景 80% 都该走 Document-aware
✅ 元数据必填字段（政企场景最低配）

source：源文件名 / 文号（如"某单位 2024-招-018 号"）

page：页码（PDF 必填，Word 可选）

chunk_id：分块编号（在这份文档内的顺序号）

section：所属章节标题（如"第三章 · 投标须知"）

doc_type：文档类型（招标 / 合同 / 政策 / SOP / 手册）

publish_date：发布日期（用于时间过滤）

hash：分块内容 hash（去重用）

目标

Step 1 · 环境准备

Step 2 · 读取 PDF（保留表格）
import pdfplumber

def read_pdf(path):
    """读取 PDF，逐页返回 (页码, 正文文本, 表格列表)"""
    pages = []
    with pdfplumber.open(path) as pdf:
        for i, page in enumerate(pdf.pages, start=1):
            text = page.extract_text() or ""
            # 关键：单独抽表格，不跟正文混
            tables = page.extract_tables()
            pages.append({"page": i, "text": text, "tables": tables})
    return pages

pages = read_pdf("招标文件.pdf")
print(f"共 {len(pages)} 页，第 1 页字数 {len(pages[0]['text'])}")
Step 3 · 清洗（去页眉页脚、修常见错字）
import re

def clean_text(text):
    # 去页眉页脚常见模式（每页重复出现的短行）
    text = re.sub(r"第\s*\d+\s*页\s*/\s*共\s*\d+\s*页", "", text)
    text = re.sub(r"招标文件\s*·\s*机密", "", text)
    # 去多余空白和换行
    text = re.sub(r"\n{3,}", "\n\n", text)
    text = re.sub(r"[ \t]+", " ", text)
    # 合并被硬换行切开的中文段落（中文行尾无标点直接接下一行）
    text = re.sub(r"([\u4e00-\u9fff，、])\n([\u4e00-\u9fff])", r"\1\2", text)
    return text.strip()

for p in pages:
    p["text"] = clean_text(p["text"])
Step 4 · 语义 + 结构混合分块
import hashlib

def chunk_by_section(pages, min_len=200, max_len=500):
    """按"第 X 章 / 第 X 条"切主结构，再控制长度"""
    chunks, buffer, current_section, current_page = [], "", "前言", 1
    section_pat = re.compile(r"(第[一二三四五六七八九十百]+[章条节][^\n]{0,40})")

    for p in pages:
        for line in p["text"].split("\n"):
            m = section_pat.search(line)
            if m:
                # 遇到新章节，先把 buffer 落盘
                if buffer.strip():
                    chunks.append({
                        "text": buffer.strip(),
                        "section": current_section,
                        "page": current_page
                    })
                current_section = m.group(1).strip()
                current_page = p["page"]
                buffer = line + "\n"
            else:
                buffer += line + "\n"
                # buffer 太长了就按句号切
                if len(buffer) >= max_len:
                    cut = buffer.rfind("。", 0, max_len)
                    if cut < min_len:
                        cut = max_len
                    chunks.append({
                        "text": buffer[:cut+1].strip(),
                        "section": current_section,
                        "page": p["page"]
                    })
                    # 保留 15% 重叠，防止关键句子被切断
                    overlap = int((cut+1) * 0.15)
                    buffer = buffer[cut+1-overlap:]

    if buffer.strip():
        chunks.append({"text": buffer.strip(), "section": current_section, "page": current_page})
    return chunks

chunks = chunk_by_section(pages)
print(f"共切成 {len(chunks)} 块，平均长度 {sum(len(c['text']) for c in chunks)//len(chunks)} 字")
Step 5 · 加元数据 + 存 JSON
import json
from datetime import datetime

def enrich_metadata(chunks, source_file, doc_type="招标文件", publish_date="2024-11-01"):
    enriched = []
    for i, c in enumerate(chunks):
        content_hash = hashlib.md5(c["text"].encode("utf-8")).hexdigest()[:10]
        enriched.append({
            "chunk_id": f"{source_file}_{i:04d}",
            "text": c["text"],
            "metadata": {
                "source": source_file,
                "page": c["page"],
                "section": c["section"],
                "doc_type": doc_type,
                "publish_date": publish_date,
                "hash": content_hash,
                "processed_at": datetime.now().isoformat(timespec="seconds")
            }
        })
    return enriched

result = enrich_metadata(chunks, "招标文件.pdf")

with open("chunks.json", "w", encoding="utf-8") as f:
    json.dump(result, f, ensure_ascii=False, indent=2)

print(f"✅ 已输出 {len(result)} 块到 chunks.json，可以进 Day 8 做 embedding 了")
Step 6 · 人肉抽检 4 关
  • 可读性：随机看 5 块，能不能一眼看懂讲的什么？
  • 结构：section 字段是不是都填对了"第 X 章 XX"？
  • 完整性：找"投标保证金"、"截止时间"这类关键点，是否被切断？
  • 元数据：source / page / section / publish_date 是不是每块都有？

🧪 案例 B · 处理一份《员工手册》Word 文档（自己练）

需求：把 30 页的 员工手册.docx 处理成分块 JSON，让员工能问"年假多少天""报销流程"这类问题。

试着自己走一遍读·清·切·存，重点思考：Word 的目录、修订痕迹、样式该怎么处理？

查看参考答案

读：用 python-docx 遍历 doc.paragraphs 拿正文，遍历 doc.tables 拿表格。表格转成 "字段名: 值" 的键值对句子。

清：过滤空段落、目录页（"第 X 章 ... 3"这种目录条目）、修订痕迹（python-docx 默认忽略 track changes，但要检查一下）。

切：Word 天然按"一级标题 / 二级标题"分层。用 paragraph.style.name 判断层级，按二级标题切块，标题本身写进 section 元数据。

存：元数据加上 doc_type="员工手册"、publish_date（从文档属性取）、heading_level（一级/二级/三级）。

from docx import Document

doc = Document("员工手册.docx")
current_section, buffer, chunks = "封面", "", []
for p in doc.paragraphs:
    style = p.style.name  # Heading 1 / Heading 2 / Normal
    if style.startswith("Heading"):
        if buffer.strip():
            chunks.append({"text": buffer, "section": current_section})
        current_section = p.text.strip()
        buffer = ""
    else:
        buffer += p.text + "\n"
if buffer.strip():
    chunks.append({"text": buffer, "section": current_section})
🧪 案例 C · Bug case：这份分块结果有 5 处质量问题，你能挑出来吗？

场景：某个下属用 PyPDF2 + text[i:i+500] 处理了一份招标文件，产出如下分块（节选 3 块）。找出至少 5 处质量问题。

查看参考答案（5 处修法）

问题 1 · 页眉页脚未清洗："招标文件 · 机密第 1 页 / 共 60 页" 混在正文里。修法：加正则 re.sub(r"第\s*\d+\s*页.*", "", text)。

问题 2 · "投标截止时间"被从中间切开：chunk 0 结尾"截止时"、chunk 1 开头"间为"。修法：换 Document-aware 分块，按章节/句号切，不按字数硬切。

问题 3 · "投标保证金 500000 元"被切成 chunk 1 的"5000"和 chunk 2 的"00 元"——语义完全断裂。修法：分块之间保留 15% 重叠。

问题 4 · 元数据全无：只有 id 和 text，没有 source / page / section / publish_date。修法：加 metadata 字段，政企场景合规硬要求。

问题 5 · "评标办法："后面就没了——表格被切没了。修法：用 pdfplumber.extract_tables() 单独抽表格，转成"评分项 XX / 分值 XX / 说明 XX"的语义句子。

面试金句："这三块分块，其实告诉我一件事——预处理没做对，后面 embedding 换 5 个模型都救不回来。"

📝 五、5 题小测验

建议先自己想 20 秒再点开答案。答错也别慌——错项解析比正确答案更值钱。

Q1 · 处理带表格的 PDF，下面哪个库最不该用？
  • A. pdfplumber
  • B. unstructured
  • C. PyPDF2
  • D. PaddleOCR
✅ 答案：C

PyPDF2 只能提取文本流，表格里的单元格会散成"值1值2值3"混在正文里，或者直接丢失。带表格的 PDF 用它就是自杀。

❌ 错项解析

A pdfplumber 是首选——它对表格解析最好，能拿到二维数组结构。B unstructured 也可以——版面识别强，适合复杂布局。D PaddleOCR 是扫描版 PDF 的选择——文本 PDF 用它也不合适（大材小用还慢），但至少不会像 PyPDF2 那样把表格丢掉。

Q2 · 一份 60 页的《施工招标文件》，最合适的分块策略是？
  • A. Fixed，每 500 tokens 硬切，简单可靠
  • B. Semantic，按段落语义相似度切
  • C. Document-aware，按"第 X 章 / 第 X 条"切，超长的再二次切
  • D. 不用切，整份 PDF 直接扔进 embedding
✅ 答案：C

招标文件是典型的强结构文档——"第一章 招标公告 / 第二章 投标人须知 / 第三章 评标办法"，每章每条相对独立。Document-aware 切法保证语义完整、还能把 section 写进元数据，后期能按章节过滤。

❌ 错项解析

A Fixed 会把"投标保证金 500000 元"从中间切开——检索关键条款答不上。B Semantic 比 Fixed 好，但没利用招标文件的强结构——效果不如 Document-aware。D 是最典型的新手错误——一份 60 页整体 embedding，检索时根本不知道匹配到了哪一段，且大部分 embedding 模型有 token 上限，超长会被截断。

Q3 · 关于元数据，下面哪种说法是错的？
  • A. 元数据可以让后期按时间/来源/文号过滤
  • B. 政企场景，元数据是合规硬要求
  • C. 第一版可以先不加，等有需求了再补
  • D. hash 字段可以用来做分块去重和更新检测
✅ 答案：C

C 是常见误解。第一版不加元数据，后期要补就得重新跑全流水线——历史所有向量作废、重新 embedding、重新入库，成本比第一版直接加高 5-10 倍。政企 RAG 项目最贵的返工之一就是"补元数据"。

❌ 错项解析

A 正确——元数据过滤是 RAG 优化最省力的一环。B 正确——政企客户合规部会问"这段答案是哪份文档说的？"，没有 source/page 你答不上。D 正确——hash 用来判断分块是否变化，节省重复 embedding 成本。

Q4 · 处理 Excel 文件，下面哪种做法最推荐？
  • A. 用 pandas.read_excel 读进来，直接 df.to_string() 塞进 embedding
  • B. 转成 CSV，按行 embedding
  • C. 每行（或每几行）转成一句自然语言描述，再 embedding
  • D. 截图整张表，走 OCR 处理
✅ 答案：C

Excel 里的数据要变成"人话"再 embedding。例如"2024 年第 3 季度，华东区销售额 830 万，环比增长 12%，负责人张伟"——这样一句话，embedding 出来的向量对"华东销售"这类查询匹配度极高。原始表格塞进去，向量里全是数字符号噪声。

❌ 错项解析

A 是新手最爱写的方式——但 df.to_string() 输出的伪表格排版，embedding 完全捕捉不到语义。B 按行 embedding 好一点，但一行"华东,830,12%,张伟"没有字段名，还是不像人话。D 是本末倒置——Excel 是结构化数据，走 OCR 反而丢了结构。

Q5 · 综合题——预处理质量校验 4 关，如果 4 关都过，是否就一定能保证 RAG 效果好？
  • A. 是的，4 关全过 = RAG 效果一定好
  • B. 不是，4 关只是"预处理"这一步的合格线，后面还有 embedding、检索、重排、生成 4 步各自的天花板
  • C. 不是，4 关过了也可能因为 LLM 幻觉答错
  • D. B 和 C 都对
✅ 答案：D

4 关是必要不充分条件——过不了这 4 关，后面再优化都白搭；但过了 4 关，还要经过 embedding 模型好不好、Top-K 调没调、有没有重排、prompt 写没写好等一系列关卡。今天学的只是 RAG 的地基。

❌ 错项解析

A 错在夸大预处理作用——预处理只是 RAG 的一环，不是全部。B 单独对，但漏了"LLM 幻觉"这个下游问题。C 单独对，但漏了"检索环节也可能翻车"。B 和 C 合起来才完整——这也是为什么 Day 8 讲检索优化、Day 9 讲端到端 Demo，你要建立全链路视角。

💼 六、面试金句预埋

预处理决定 RAG 天花板 "我做 RAG 项目的顺序不是先选模型——是先把文档预处理这一环做扎实。因为我见过太多项目，模型 embedding 换了三家、Top-K 从 5 调到 20，效果依然烂——回过头一看，喂进去的分块本身就是碎片，天花板早就锁死了。预处理没做对，后面白花力气。"
结构保留意识 "拿到一份 PDF，我第一件事不是切分，是判断它有没有结构——章节、条款、表格。有结构就走 Document-aware 分块，让每一块跟原文的语义边界对齐。政企文档 80% 都有强结构，硬用 Fixed 或 Semantic 切，就是浪费客户的合规红利。"
元数据文化 "元数据是 RAG 的第二次机会——分块切错了很难救，但只要 source/page/section/date 都齐全，后期检索出问题至少能过滤、能追溯、能追责。政企项目上线前，客户合规部会挨个字段查。第一版就要把元数据设计好，别等半年后返工。"

📓 心得笔记

⚠️ 今天最反直觉的 3 件事

1. RAG 效果的天花板 70% 在预处理，模型换来换去只能救 30%。（这也是为什么资深 FDE 花在预处理上的时间比选模型多。）

2. Excel 里的数据要变成"人话"再 embedding，直接 to_string() 塞进去是新手陷阱。

3. 元数据不是"锦上添花"，是政企场景的合规硬要求。第一版就上，成本最低。
