📖 二、核心讲解

是什么：LLM 部署的 3 种模式

大白话——大模型跑在哪儿、谁的机器、谁交电费，就这三种：

模式白话解释典型场景成本结构
公有云 API调阿里通义/百度千帆/OpenAI 的接口，按 token 计费初创、互联网、非涉密业务按量付费，无硬件投入
私有化部署模型下载到客户机房，GPU 服务器自己跑银行、政务、央国企涉密硬件 200 万+ 一次性 + 运维
混合模式敏感数据走本地小模型，非敏感走 API 大模型大多数政企的最优解本地基础机器 + API 按量

反直觉的地方：90% 的政企客户张口就说"要私有化"，但其中大概一半，做混合模式反而更安全、更便宜、效果更好。为什么？因为私有化能跑起来的模型，普遍比公有云顶配模型弱一代。

□ □ □ 四维选型口诀 □ □ □
敏 · 量 · 钱 · 规
数据敏感度 · QPS 量级 · 成本预算 · 合规要求 — 缺一项就问不出真答案

为什么：FDE 视角下的三个大坑

🚨 坑 1 · 政企默认要私有化——其实非涉密业务用国内公有云 + VPC 加密完全够

客户信息部门开口就说"我们是央企/政务/金融，数据当然不能出内网，必须私有化"。你如果顺着说"好我们做私有化方案"，就掉坑了。

真相：央国企的数据也分级。C1（公开信息）、C2（内部可加密上云）、C3（不出境）、C4（不出内网涉密）——真正必须私有化的只有 C3、C4。而 员工问答里的制度条款、办事咨询里的政策解读、员工报销的规则解释 这些恰恰是 C1/C2，走国内公有云 + VPC 私有链路 + API 密钥托管完全合规。

正确姿势：拿到需求先做数据分级——"我把这次涉及的所有数据字段列一下，我们逐项判断是哪一级"，然后再谈方案。

🚨 坑 2 · 只看采购成本不看 TCO——私有化硬件+人力运维一年比 API 还贵

客户说"API 每天要几千块，一年就 100 多万，太贵了，我们买 8 张 A800 一次性搞定"。你算给他听：8×A800 服务器 200 万一次性 + 电费/机房托管 15 万/年 + 专职运维 40 万/年 + 模型迭代升级 20 万/年 + 备件冗余 10 万/年——第一年 285 万，第二年往后每年 85 万。而 QPS 20 左右的 API 一年也就 60-80 万。

正确姿势：永远算 3 年 TCO（Total Cost of Ownership），把硬件折旧、人力、机房、升级、备件全算进去。低于 100 QPS 的场景，3 年 TCO 私有化基本必输。

🚨 坑 3 · 混合模式想都不想——涉密走本地/非涉密走 API 反而最经济

客户信息部长最怕的是"数据泄露我背锅"，业务部长最怕的是"效果差业务不用"。这两个诉求看起来对立，其实混合模式一把解决——敏感数据（合同全文、客户身份证、内部薪资）在本地脱敏后处理，非敏感任务（通用问答、公开政策查询、格式转换）走公有云顶配模型。

正确姿势：你要在第一次架构讨论会上主动提出混合模式选项，别等客户想。因为客户大概率想不到，他脑子里只有非黑即白的两个选项。

🧭 PM 行动指南：给客户讲选型的 4 步

Step A · 先聊数据敏感度——拿一张表，把涉及的数据字段（用户输入、知识库、日志、输出）逐项贴 C1-C4 标签。这一步决定后面所有推演。

Step B · 再算量——预估 QPS 峰值和日均调用量。政企内部业务 QPS 通常 1-30 之间，比互联网小两个数量级，别用互联网思维。

Step C · 再算钱——3 年 TCO 三种模式并列对比。硬件成本很直观，隐性成本（运维、升级、备件）要主动加进去。

Step D · 最后过合规——等保 2.0 三级/关基/涉密三个门槛。合规是一票否决项，放最后是因为前三步已经把 80% 的选择过滤掉了，合规只做最终确认。

怎么用：四维决策树

1
数据敏感度（敏）——C1 可上云 / C2 加密后可上云 / C3 不出境（可用国内公有云）/ C4 不出内网（必须私有化）。关键：这个分级不是你定的，是客户信息安全部门定的，你去要一份《数据分类分级表》，避免自己拍脑袋。
2
QPS 量级（量）—— < 10 QPS 用 API（硬件闲置浪费）/ 10-100 QPS 混合（部分本地部分 API）/ > 100 QPS 建议私有化（API 按量成本会飙升）。算 QPS 要看峰值，不是均值。政企场景通常"日常 5 QPS 但月底突发 60 QPS"，按 60 算。
3
成本预算（钱）——私有化硬件门槛 8×A800/H20 一台服务器约 200 万起（跑一个 32B/70B 参数模型合适）。API 按量，通义千问 Max 输入约 20 元/百万 token、输出 60 元/百万 token。你要能张口就说这个基准数字，客户才服你。
4
合规要求（规）——等保 2.0 二级（一般政务/企业业务）/ 三级（重要政务、金融业务、公共服务）/ 关键信息基础设施（关基，能源、金融、水利等）/ 涉密。三级以上多数走私有化或行业专有云；二级国内公有云一般能过。
5
综合决策——敏 C4 或 合规关基/涉密 → 私有化；敏 C1/C2 且 QPS < 30 且 合规二级 → 公有云 API；其他 → 混合模式（默认答案，60% 政企项目最优解）。

📌 案例 A · 某国有银行「智能客服 Agent」选型（跟着做）
客户背景

某省级国有银行，要做一个内部智能客服 Agent，帮柜员回答业务规则问题（转账限额、外汇政策、开卡资料要求等）。要接入知识库 300+ 篇规章。

Step 1 · 数据敏感度（敏）
  • 用户输入（柜员提问）：C2——含分行名、员工工号，加密后可上云
  • 知识库（规章制度）：C2——内部非涉密，加密后可上云
  • 日志（问答记录）：C3——涉及内部业务口径，不出境
  • 输出（AI 回答）：C2——同知识库

→ 综合 C2/C3，可以用国内公有云 + VPC 私有链路。

Step 2 · QPS 量级（量）

全行 2000 柜员，业务时段假设 20% 同时活跃，均值 3 QPS，峰值（月底结算日）估 20 QPS。→ 属于低量级，API 完全够。

Step 3 · 成本预算（钱）
方案一次性3 年总备注
公有云 API0约 180 万Qwen-Max 按量，日均 5 万 token
私有化（8×A800）200 万约 405 万+ 运维 40 万/年 + 电费/机房 15 万/年 + 升级 10 万/年
混合（本地 7B + API 补漏）50 万约 230 万2×A10 本地跑 Qwen-7B 处理敏感字段，其余走 API
Step 4 · 合规要求（规）

银行核心系统等保三级，客服辅助系统一般二级。业务不涉决策，AI 输出前置人工确认即可满足审计。

Step 5 · 结论

推荐混合模式。敏感字段（客户身份证号、账号）在本地 Qwen-7B 上做脱敏与初步意图分类，脱敏后的问题+知识库检索片段走 Qwen-Max API 生成回答。3 年 TCO 比纯私有化省 175 万，效果比纯本地强一档，合规无风险。

面试金句预埋："客户嘴里的'必须私有化'，翻译过来常常是'我不想背数据泄露的锅'。混合模式把敏感数据留在本地就够了，其余按量走 API 反而合规审计更好过。"

客户原话："我们是国资委下面的央企，业务重要，你给我们私有化部署 GPT-4 那个级别的模型，本地跑起来。预算 800 万一次性到位。"

查看参考答案

核心事实：GPT-4 级别的模型（如 GPT-4、Claude 3.5、Gemini Ultra）不开源、不允许私有化部署。你根本买不到。这是第一层要澄清的。

可以私有化的最强开源模型：DeepSeek-V3 671B、Qwen2.5-72B、GLM-4-9B、Llama-3.3-70B。这些跑推理需要 8×H20 或 8×A800 一台，约 200-300 万硬件。跑 DeepSeek-V3 完整版需要 2-4 台机器互联，约 500-800 万起，且专业运维一年 100 万起。

更关键的问题：就算你花 800 万私有化，效果只是最新公有云顶配模型的 80%——因为开源模型迭代滞后 3-6 个月，你等于花高价买了个"上一代"。

推荐替代：混合方案——2×A100 本地跑 Qwen-32B 处理涉密数据脱敏和敏感任务（一次性 60 万），非涉密走通义千问 Max/DeepSeek API（按量 3 年约 80 万）。总 3 年成本 200 万，剩下 600 万做业务定制、prompt 工程、评测集建设、灰度运营——这些才是让 AI 真正落地的钱。

话术："张总，坦白讲，GPT-4 级别的模型今天全世界没有一家能私有化，OpenAI 不卖。您 800 万预算，我建议这样切——50 万买本地机器把涉密的活干了，80 万走 API 把通用任务干了，剩下 670 万投在业务侧调优。这样一年后您得到的是真能用的系统，而不是一堆吃电的服务器。"

📝 五、5 题小测验

建议先自己想 20 秒再点开答案。答错也别慌——错项解析比正确答案更值钱。

Q1 · 客户是省级政务，QPS 峰值 15，数据 C2 加密后可上云，等保三级——首选方案是？
  • A. 私有化 8×A800 跑 Qwen-72B
  • B. 混合模式，本地小模型兜底 + 国内公有云 API 主链路
  • C. 用 OpenAI GPT-4 API
  • D. 私有化 1×A10 跑 Qwen-7B
✅ 答案：B

敏 C2、量 < 30 QPS、规等保三级、政务客户。C2 允许加密上云，QPS 低说明私有化 TCO 划不来，等保三级需要本地兜底与可解释——混合模式全部命中。

❌ 错项解析

A 错在杀鸡用牛刀——15 QPS 用 8×A800 有 90% 的算力闲置，3 年 TCO 至少 400 万，客户预算撑不住。C 错在跨境合规——政务数据出境需过安全评估，且 GPT-4 数据在境外，PIPL 直接封死。D 错在效果偏低——政务问答的政策语言复杂，7B 模型准确率通常不足 75%，客户不会验收。

Q2 · "私有化部署一台 8×A800 服务器 3 年成本"最接近下列哪个数字？
  • A. 200 万
  • B. 250 万
  • C. 400 万
  • D. 700 万
✅ 答案：C

硬件 200 万 + 运维 120 万（40 万/年 × 3）+ 机房电费 45 万 + 模型升级 30-60 万 + 备件故障 20-30 万 ≈ 400 万。

❌ 错项解析

A 是只算硬件采购——最常见的错误，客户和不懂行的乙方都会掉进去。B 加了运维但漏了机房、升级、备件——政企机房托管一年 15 万+，跳不过。D 属于顶配私有化（8×H100 或多机集群），不是标配。

Q3 · 「敏·量·钱·规」四维中，哪一维通常是"一票否决"？
  • A. 敏（数据敏感度）
  • B. 量（QPS）
  • C. 钱（预算）
  • D. 规（合规要求）
✅ 答案：D

合规是硬门槛——等保三级/关基/涉密要求过不了，方案再优秀也上不了线。前 3 维是"选优"，第 4 维是"生死"。

❌ 错项解析

A 敏是选型输入，能推出多个可行方案，不是否决。B 量决定成本结构，是经济性问题不是准入问题。C 钱不够可以缩方案（换小模型、砍功能），不到否决层面。合规是唯一"必须过、过不了就不能上线"的门。

Q4 · 客户说"我们跑 Qwen-72B，日均 API 费 5000 块，一年 180 万太贵"——你的第一反应？
  • A. 建议改私有化，一次性买 8×A800 一劳永逸
  • B. 先看是不是所有请求都必须 72B，能不能用 32B/7B 分流降本
  • C. 换个便宜 API 厂商
  • D. 建议客户把日均 token 消耗砍一半
✅ 答案：B

降本第一原则是模型分级路由——简单意图/短问答走 7B，复杂推理走 32B，只有 20% 的真正难任务走 72B。这样能把 API 成本压到原来的 30-40%，且效果几乎不掉。这是 FDE 的标准动作，比换厂商、换部署模式都优先。

❌ 错项解析

A 是坑 2 典型场景——180 万 API 换成 400 万私有化 3 年 TCO，账没算。C 换厂商只能省 10-20%，且质量风险大，不是首选。D 砍 token 会伤害效果，且没考虑请求量是否合理，是最后的手段。

Q5 · 综合题——客户是市级税务局，要「税收政策问答 Agent」，QPS 峰值 8，等保三级+关基，涉及企业纳税信息。请给方案。

按敏·量·钱·规四维写下你的分析。

✅ 参考答案：纯私有化，走行业专有云或本地机房

敏：纳税信息是 C3-C4 敏感数据，且属关基行业。国内公有云也不合规。

量：QPS 8 极低，硬件闲置严重，但合规压过经济性。

钱：3 年 TCO 约 200 万（2×A800 跑 Qwen-32B 就够了，QPS 8 不用上 72B）。虽然贵于 API，但没得选。

规：关基 + 等保三级，必须私有化 + 内网部署。走电子政务外网或行业专有云也可以，但接口和运维复杂度高。

方案：本地 2×A800 部署 Qwen-32B + 内网向量库 + 完整日志审计。不上 72B——8 QPS 用不上，32B 政策问答准确率能到 85%+，性价比更好。

面试金句："关基和涉密项目算 ROI 的时候要认怂——合规不通过所有账都是零。"

💼 六、面试金句预埋

TCO 意识 "谈私有化 vs 公有云，我从来不看采购单价，我看3 年 TCO。硬件、运维、机房、升级、备件——这五项加起来，私有化通常比客户想的贵一倍。QPS 低于 100 的政企场景，私有化几乎必输。"
混合模式思维 "政企客户张口就说'必须私有化'，但真正需要私有化的只有 C4 涉密的那 20% 数据。剩下 80% 走混合模式——敏感数据本地脱敏，非敏感走 API——合规、成本、效果三个维度全赢。"
数据分级文化 "架构选型第一步不是聊模型，是拉客户信息安全部门做数据分类分级。C1-C4 分完，方案自己就出来了。跳过这一步的选型都是拍脑袋，上线后一改就是重构级。"

📓 心得笔记

⚠️ 今天最反直觉的 3 件事

1. "私有化最安全"是错觉——本地运维水平不够反而更容易泄露。合规看的是"是否满足要求"，不是"是否本地"。

2. 私有化能跑的最强模型比公有云顶配弱一代。你花 800 万私有化，效果不如别人花 80 万 API 调用。

3. 混合模式是 60% 政企项目的最优解，但客户默认想不到——你要主动摆到桌面上。
