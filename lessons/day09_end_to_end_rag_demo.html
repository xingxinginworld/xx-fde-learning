为什么：PM 视角下的三个大坑

🚨 坑 1 · Demo 只有后端接口没有 UI（客户看不懂 curl）

技术同学最爱交付的方式："我给你一个 API，你 curl 一下就能看到效果。"——客户当场脸黑。

政企客户绝大多数是业务口——处长、科长、评标专家。他们看不懂 curl，看不懂 JSON，看不懂 Postman。你给他们一个能"输入问题按回车看答案"的网页，10 秒钟他就懂了 RAG 值不值得投。

正确姿势：Streamlit 或 Gradio，20-50 行代码就能搭一个能演示的 UI。这一步不是可选，是必选。

🚨 坑 2 · 演示前不测试 Bad Case（现场翻车）

Demo 你自己测的问题都能答对——因为你只测你自己想过的。到了客户现场，评标专家一句"你这个能不能答'如果两家投标价一样，谁中标'？"——你的 RAG 检索不到具体条款，LLM 开始编，编出来一段跟法规相反的答案，客户当场脸变了。

正确姿势：演示前让 3 个不同角色（业务/合规/技术）各出 5 个问题跑一遍，把答错的 Bad Case 都收集起来。演示时主动亮出："这个类型的问题我们暂时兜底转人工"——比翻车强 100 倍。

🚨 坑 3 · Demo 硬编码 Key / 路径 / 端口，换台电脑就跑不了

Demo 在你的开发机好好的——路径写死 D:\project\data、Key 写死代码里、端口写死 8501。到了客户现场用他们借的电脑，或者你用 U 盘拷过去，全炸。

更惨的：出差前 5 分钟才发现依赖没装全，pip 又要过 VPN，2 小时装不完。

正确姿势：三条硬规矩——① Key 走环境变量 os.getenv("DASHSCOPE_API_KEY")；② 路径全部 Path(__file__).parent 相对；③ 出差前打包成 requirements.txt + .env.template，换机器 10 分钟能重跑。

🧭 PM 行动指南：Demo 演示前必过 5 关

关 1 · 能启动：换台电脑 pip install -r requirements.txt + streamlit run app.py，10 分钟内能跑起来。

关 2 · UI 能看：主流程按钮/输入框排版顺畅，Loading 有反馈，不是白屏等 20 秒。

关 3 · 主流程通：至少 10 条高频问题（客户业务口出的）都能答对。

关 4 · Bad Case 已知：知道自己 Demo 在哪些问题上会翻车，演示时主动说清并给兜底方案。

关 5 · 换机器能跑：Key 环境变量、路径相对、依赖清单齐全。U 盘拷贝到新电脑能起来。

5 关全过再进客户会议室。任意一关不过就是自找翻车。

怎么用：把前 5 天的组件组装的 4 步

1
数据管道模块——把 Day 7 的预处理脚本封装成 build_index.py：读 PDF → 分块 → embedding → 存 FAISS。这是离线一次性跑的，不用每次启动都跑。
2

Web UI——app.py，用 Streamlit。20-50 行代码，含输入框、消息历史、Loading 状态、引用出处展开框。启动一行：streamlit run app.py。

Step 2 · build_index.py（离线跑一次）
import os, json, hashlib
from pathlib import Path
import pdfplumber, numpy as np, faiss
from dashscope import TextEmbedding
from dotenv import load_dotenv

load_dotenv()
BASE = Path(__file__).parent
DATA_DIR = BASE / "data"
INDEX_DIR = BASE / "index"
INDEX_DIR.mkdir(exist_ok=True)

def read_and_chunk(pdf_path, chunk_size=400, overlap=60):
    """Day 7 的预处理：读 → 清 → 切 → 加元数据"""
    chunks = []
    with pdfplumber.open(pdf_path) as pdf:
        buffer = ""
        for i, page in enumerate(pdf.pages, start=1):
            text = (page.extract_text() or "").replace("\n\n", "\n")
            buffer += text + "\n"
            while len(buffer) >= chunk_size:
                cut = buffer.rfind("。", 0, chunk_size) + 1
                if cut < chunk_size // 2:
                    cut = chunk_size
                chunks.append({"text": buffer[:cut].strip(), "page": i,
                              "source": pdf_path.name})
                buffer = buffer[cut - overlap:]
        if buffer.strip():
            chunks.append({"text": buffer.strip(), "page": i, "source": pdf_path.name})
    # 加元数据
    for j, c in enumerate(chunks):
        c["chunk_id"] = f"{pdf_path.stem}_{j:04d}"
        c["hash"] = hashlib.md5(c["text"].encode()).hexdigest()[:10]
    return chunks

def embed_batch(texts, batch=25):
    vecs = []
    for i in range(0, len(texts), batch):
        resp = TextEmbedding.call(model="text-embedding-v3", input=texts[i:i+batch])
        vecs.extend([item["embedding"] for item in resp.output["embeddings"]])
    return np.array(vecs, dtype="float32")

if __name__ == "__main__":
    all_chunks = []
    for pdf in DATA_DIR.glob("*.pdf"):
        print(f"处理 {pdf.name}...")
        all_chunks.extend(read_and_chunk(pdf))
    print(f"共 {len(all_chunks)} 分块")
    # embedding
    vectors = embed_batch([c["text"] for c in all_chunks])
    # 建 FAISS 索引（内积/余弦）
    faiss.normalize_L2(vectors)
    index = faiss.IndexFlatIP(vectors.shape[1])
    index.add(vectors)
    faiss.write_index(index, str(INDEX_DIR / "vecs.faiss"))
    json.dump(all_chunks, open(INDEX_DIR / "chunks.json", "w", encoding="utf-8"),
              ensure_ascii=False, indent=2)
    print("✅ 索引构建完成")
Step 3 · retriever.py（在线检索）
import json
from pathlib import Path
import faiss, numpy as np
from dashscope import TextEmbedding, TextReRank

BASE = Path(__file__).parent
INDEX = faiss.read_index(str(BASE / "index" / "vecs.faiss"))
CHUNKS = json.load(open(BASE / "index" / "chunks.json", encoding="utf-8"))

def embed(text):
    resp = TextEmbedding.call(model="text-embedding-v3", input=[text])
    return np.array([resp.output["embeddings"][0]["embedding"]], dtype="float32")

def retrieve(query, top_k=5, coarse_k=20, threshold=0.5):
    """Day 8 的 5 维度：向量粗筛 → 阈值 → 重排 → Top-K"""
    q = embed(query)
    faiss.normalize_L2(q)
    scores, ids = INDEX.search(q, coarse_k)
    # 阈值过滤
    candidates = [(CHUNKS[i], float(s)) for i, s in zip(ids[0], scores[0]) if s >= threshold]
    if not candidates:
        return []
    # 重排
    resp = TextReRank.call(
        model="gte-rerank",
        query=query,
        documents=[c[0]["text"] for c in candidates],
        top_n=top_k
    )
    return [candidates[r["index"]][0] for r in resp.output["results"]]
Step 4 · generator.py（LLM 生成）
import json
from dashscope import Generation

SYSTEM_PROMPT = """你是政府文件问答助手。基于用户提供的<参考资料>回答问题。
硬规矩：
1. 只用参考资料里的信息，不要编造
2. 参考资料没写的，直接说"文档中未提及"
3. 每个事实要标出处（来源文件+页码）
4. 输出严格 JSON 格式"""

def generate(query, contexts):
    """Day 4 API + Day 5 结构化输出"""
    context_str = "\n\n".join(
        f"[{i+1}] 来源：{c['source']} 第{c['page']}页\n{c['text']}"
        for i, c in enumerate(contexts)
    )
    prompt = f"""<参考资料>
{context_str}
</参考资料>

用户问题：{query}

请以 JSON 格式回答，字段：
- answer: 直接回答
- citations: 引用列表，每项含 source（文件名）和 page（页码）
- confidence: 置信度 high/medium/low"""

    resp = Generation.call(
        model="qwen-plus",
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": prompt}
        ],
        result_format="message",
        response_format={"type": "json_object"}
    )
    text = resp.output.choices[0].message.content
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        return {"answer": text, "citations": [], "confidence": "low"}
Step 5 · app.py（Streamlit UI · 只有 40 行）
import streamlit as st
from dotenv import load_dotenv
from retriever import retrieve
from generator import generate

load_dotenv()

st.set_page_config(page_title="政府文件问答助手", page_icon="📜", layout="wide")
st.title("📜 政府文件问答助手")
st.caption("Powered by 阿里云百炼 · 基于 RAG 的政策文件检索问答系统 · Demo v1")

# 会话历史
if "messages" not in st.session_state:
    st.session_state.messages = []

# 展示历史消息
for msg in st.session_state.messages:
    with st.chat_message(msg["role"]):
        st.markdown(msg["content"])
        if "citations" in msg:
            with st.expander(f"📚 参考出处（{len(msg['citations'])} 条）"):
                for c in msg["citations"]:
                    st.write(f"- {c.get('source','')} · 第 {c.get('page','?')} 页")

# 输入框
if query := st.chat_input("请输入你的问题，例如：投标截止日期是什么时候？"):
    st.session_state.messages.append({"role": "user", "content": query})
    with st.chat_message("user"):
        st.markdown(query)

    with st.chat_message("assistant"):
        with st.spinner("检索中..."):
            contexts = retrieve(query, top_k=5)
        if not contexts:
            answer = "抱歉，知识库里没有找到相关内容，建议转人工咨询。"
            st.warning(answer)
            st.session_state.messages.append({"role": "assistant", "content": answer})
        else:
            with st.spinner("生成回答..."):
                result = generate(query, contexts)
            st.markdown(result["answer"])
            with st.expander(f"📚 参考出处（{len(result['citations'])} 条）"):
                for c in result["citations"]:
                    st.write(f"- {c.get('source','')} · 第 {c.get('page','?')} 页")
            st.caption(f"置信度：{result.get('confidence','?')}")
            st.session_state.messages.append({
                "role": "assistant",
                "content": result["answer"],
                "citations": result["citations"]
            })

🧪 案例 C · Bug case：出差前电脑跑得好好的，客户现场部署 3 个报错，怎么诊断？（自己练）

场景：你带笔记本到某单位某分公司做 Demo。客户借给你一台内网笔记本让你演示。运行 streamlit run app.py 后连爆 3 个错：

  • 报错 1：FileNotFoundError: [Errno 2] No such file or directory: 'D:\\project\\gov_rag_demo\\data\\招标.pdf'
  • 报错 2：ModuleNotFoundError: No module named 'faiss'
  • 报错 3：OSError: [WinError 10048] 通常每个套接字地址...只能使用一次 (端口 8501)

给出 3 层修复思路：紧急止血 / 现场兜底 / 未来防范。

查看参考答案（3 层修复）

报错 1 · 路径硬编码

  • 止血：代码里 D:\project\... 全部改成 Path(__file__).parent / "data"。
  • 兜底：如果 data/ 空，代码提示"请把 PDF 放到 data/ 下再启动"，别直接崩。
  • 防范：Demo 项目里永远不许出现绝对路径。写完 grep 一遍 D:\、C:\、/Users/。

报错 2 · 依赖没装全

  • 止血：pip install faiss-cpu 补上。政企内网可能没外网，提前下好 whl 包带在 U 盘。
  • 兜底：requirements.txt 必须锁版本号（用 == 不用 >=）。演示前一定跑 pip install -r requirements.txt 走一遍。
  • 防范：政企出差包必带——requirements.txt、.env.template、packages/*.whl（离线包）、Python 安装包本身。

报错 3 · 端口冲突

  • 止血：streamlit run app.py --server.port 8888，换个端口。
  • 兜底：启动脚本里加逻辑，8501 被占就自动往上找空端口。
  • 防范：政企内网端口管制严——提前跟客户 IT 确认可用端口，别到现场才发现 8501 是他们的 OA 端口。

面试金句："我做 Demo 演示的规矩是——出差前打包一份'可移植清单'：requirements 锁版本、路径全相对、Key 走环境变量、依赖离线包备份。现场部署翻车这种事，从来不该发生在正式 FDE 身上。"

  4. 端口占用 · 提前问客户 IT，或加自动换端口逻辑
  5. 网络不通 · 内网测试时确认 API 域名能通（百炼是 dashscope.aliyuncs.com）
  6. Bad Case 现场翻车 · 演示前 3 个角色出题各 5 条
  7. LLM 编造答案 · Prompt 硬规矩 "没写就说没写"，加 confidence 字段
  8. 检索超时 · FAISS 用 IndexFlatIP 就够快；Reranker 加超时兜底
  9. 中文字体乱码 · Streamlit 默认支持，别自己指定 font-family
  10. Session 状态丢失 · 所有历史进 st.session_state，别用全局变量

📝 五、5 题小测验

建议先自己想 20 秒再点开答案。答错也别慌——错项解析比正确答案更值钱。

Q1 · 客户会议室演示 Demo，只带一个 API + Postman 集合可以吗？
  • A. 可以，反正接口能通就行，客户想看细节我给他看 JSON
  • B. 可以，节省时间不用做 UI
  • C. 不可以，政企客户业务口看不懂 API 和 JSON，必须有网页 UI 才能让他理解
  • D. 视情况——技术客户可以，业务客户不行
✅ 答案：C

政企客户 90% 场景决策方是业务口——处长、科长、评标专家。他们看不懂 API 也没兴趣看。Streamlit 20-50 行代码就能搭一个能演示的 UI，成本极低但直接决定客户对项目的观感。

❌ 错项解析

A 是典型 IT 思维——但你的客户不是 IT。B "节省时间"是伪节省——省了 30 分钟 UI，损失一个百万级项目。D 看似合理，实际不成立——政企场景决策链上一定有非技术的领导，永远按最保守的口径准备（做 UI）。

Q2 · 关于 Demo 演示前的 5 关校验，下面哪一关最容易被忽视？
  • A. 能启动（换电脑能跑）
  • B. UI 能看（排版顺畅）
  • C. 主流程通（10 条问题能答）
  • D. Bad Case 已知（知道哪些会翻车）
✅ 答案：D

Bad Case 是被最多人忽视、也最容易现场翻车的一关。前 3 关都是"能不能演示"，Bad Case 是"演示时会不会翻车"——需要主动请业务/合规/技术三个不同角色出题跑一遍，这个动作绝大多数团队不做。

❌ 错项解析

A B C 都很重要，但都是"事前能自己发现"的问题。D 特殊在——你自己测的问题不会翻车（因为你只测你会的），只有让第三方出题才能暴露真正的 Bad Case。演示时主动说清 Bad Case，比翻车强 100 倍。

Q3 · build_index.py 应该在什么时候跑？
  • A. 每次启动 streamlit run app.py 时自动跑一遍
  • B. 用户每次提问时跑一遍
  • C. 离线一次性跑，之后只在数据更新时重跑
  • D. 每天定时跑一次
✅ 答案：C

Embedding 建索引是重活——1000 分块可能要 2-5 分钟、消耗 API 配额。这一步天然是离线一次性的：数据没变就不用重跑。做到 index/ 里落盘后，在线服务只读索引，冷启动秒开。

❌ 错项解析

A 每次启动重跑——启动要等 5 分钟，客户当场关掉。B 每次提问重跑——单次查询等 5 分钟，用户体验灾难。D 每天定时——数据没变的时候完全浪费；数据频繁更新的场景才需要。正确做法是：建索引是"离线批处理"，检索是"在线毫秒响应"，这两条链路要分开设计。

Q4 · 演示时客户临时问一个你没测过的问题，Demo 检不到，LLM 开始"编"，你现场应该怎么做？
  • A. 装作没看见，继续演示下一个问题
  • B. 主动指出"这个答案我们不确定"，并解释兜底方案
  • C. 现场改代码修 bug，让客户等
  • D. 结束演示，回去重做
✅ 答案：B

最专业的做法是主动亮问题："这个类型的问题我们目前在知识库里覆盖度不够，正式版会加'置信度低自动转人工'的兜底。您刚提的这个我记下来，作为下版重点测试用例。"——把翻车变成"你有 Bad Case 意识 + 有下版计划"的信任建立机会。

❌ 错项解析

A 装作没看见——客户不是傻子，他会记住你在编。C 现场改代码——不专业、也解决不了。D 结束演示——一场演示 30 分钟没了，客户对你信心大跌。Demo 的目的不是"零翻车"，是"翻车后依然显得靠谱"。

Q5 · 综合题——把 Day 4-8 组件组装成端到端 Demo，你会在架构上做哪些"可移植性"设计？至少列 4 条。
✅ 参考答案（至少 4 条）
  1. Key 走环境变量——所有 API Key 从 .env 读，代码里绝无明文。提交 .env.template 到 git，真实 .env gitignore。
  2. 路径全相对——用 Path(__file__).parent，绝无 D:\...、C:\...、/Users/... 硬编码。
  3. 依赖锁版本——requirements.txt 用 == 精确版本；提前下好离线 .whl 包塞 U 盘，应对政企内网。
  4. 索引和源代码分离——build_index.py 离线跑；index/ 目录里的 vecs.faiss + chunks.json 可以随代码打包也可以单独发布。
  5. 参数外置——top_k、threshold、chunk_size 这类参数放 config.yaml 或 sidebar，客户想调不用改代码。
  6. 网络失败兜底——API 调用加超时和 retry；检索空返回、LLM 报错都有清晰的 UI 提示，不白屏。
  7. 启动脚本一行——README 给出 3 行命令：pip install -r requirements.txt → python build_index.py → streamlit run app.py。任何人 10 分钟能跑起来。

面试金句预埋："Demo 的可移植性不是加分项，是 FDE 的基本功。我在客户现场部署翻车过一次之后，就形成了一个'可移植清单'——Key、路径、依赖、索引、参数、兜底、启动，7 条规矩，之后就再没在部署阶段翻过车。"

💼 六、面试金句预埋

端到端思维 "FDE 和后端工程师最大的区别是——他们交付 API，我交付一个能给客户演示的完整 Demo。数据管道、向量索引、检索、生成、UI，五个模块都是我的责任。哪一环卡住我都要能顶上。这不是全栈——是端到端交付意识。"
演示纪律 "我做 Demo 演示有一套纪律：演示前必过 5 关——能启动、UI 能看、主流程通、Bad Case 已知、换机器能跑。5 关全过再进客户会议室。演示时主动亮 Bad Case 边界，比现场翻车强 100 倍。这个套路让我在某单位评标 Agent 项目里没有一次 Demo 翻车。"
可移植性 "Demo 的可移植性，是新手 FDE 和资深 FDE 分水岭。Key 走环境变量、路径全相对、依赖锁版本、离线包备份——这几条不做，出差到客户现场用他们借的电脑一跑，全炸。我的每个 Demo 项目都有一份'可移植清单'，出差前 30 分钟能确认全通过。"
