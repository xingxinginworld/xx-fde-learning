# 结营项目（Capstone）评分表 · 群主专用

> 配合 `capstone/README.md`（题目与交付物要求）使用。
> 评分原则：**先跑通，再打分**。任何交付物打不开 / 跑不起来，对应维度直接 ≤ 一半分。
> 打分完成后，把分数记入 `capstone/results.json`（台账），学员才具备中级证书签发资格。

---

## 一、通过硬闸（先查这个，不满足直接不通过）

| 硬闸 | 不满足的后果 |
|------|--------------|
| 4 项交付物齐全（系统 + 验收文档 + 架构图/适配分析 + ≥3 Bad Case） | 缺 1 项直接不通过（可补交后重评，限 1 次） |
| 系统**可运行**（按学员运行说明能在评审环境跑通） | 跑不起来 → 功能/效果/性能/异常四维度均 ≤ 各半分 |
| 环境适配单项 **≥ 12 分** | 不通过（无论总分多高） |
| 红线违规（出现真实单位名 / 日志含密钥 / 未说明数据出域） | 直接不通过，且需书面说明整改 |
| **总分 ≥ 70 分** | 不通过 |

## 二、五维度评分锚点

每维度按锚点就近取分。**锚点之间可插值**（如准确率 85% 介于 18~22 之间，记 20）。

### 1. 功能完整性（20 分）——能不能答

| 分档 | 锚点 |
|------|------|
| 17–20 | 检索→生成闭环完整；预算/截止日/资质类核心问法全部可答；支持多轮追问或澄清 |
| 12–16 | 闭环完整，核心问法可答，但个别问法需换个说法才能答出 |
| 7–11 | 能答但覆盖窄（如只支持单轮、只支持某一类问题） |
| 0–6 | 只能硬跑通 demo 路径，或检索/生成链路有明显断点 |

### 2. 效果质量（25 分）——答得准不准

评审现场用**官方 10 题 QA 集**（见下文附录）+ 从学员数据中抽 2 题，共 12 题实测。

| 分档 | 锚点（12 题实测答对数） |
|------|------|
| 21–25 | ≥11 题准确，且每答均附**原文引用来源**（章节/页码/段落可回溯） |
| 16–20 | ≥9 题准确，多数答案有引用来源 |
| 11–15 | ≥7 题准确，引用来源时有时无 |
| 0–10 | <7 题准确，或答案通顺但大量「幻觉式编造」 |

> 「准确」定义：事实与标书原文一致。引用了但引错位置的，算半对。

### 3. 性能（15 分）——快不快、稳不稳

| 分档 | 锚点 |
|------|------|
| 13–15 | 单次响应 P50 ≤ 5s（含生成）；有并发/缓存设计说明且**可运行验证** |
| 8–12 | 单次响应 P50 ≤ 10s；有性能设计说明但未实测或思路单薄 |
| 4–7 | 响应 10–30s；基本无性能设计 |
| 0–3 | >30s 或频繁超时挂死 |

### 4. 异常兜底（20 分）——不会的敢不敢说不会

评审现场出 3 个刁钻 case：①标书里根本没提的问题 ②语义模糊问题 ③超长/乱码脏输入。

| 分档 | 锚点 |
|------|------|
| 17–20 | 3 个 case 全部得体拒答/澄清，不编造；有错误日志可查；检索为空有明确兜底话术 |
| 12–16 | 2 个 case 处理得体，1 个含糊其辞 |
| 7–11 | 1 个 case 处理得体，其余有幻觉风险 |
| 0–6 | 对没提的问题也强行编答案（**此项 0 分档一票降到总分 -10**） |

### 5. 环境适配（20 分）——政企环境能不能落地（硬闸项）

| 分档 | 锚点 |
|------|------|
| 17–20 | 架构图清晰可讲；**白名单/端口/出域**逐项说明；离线或私有化部署方案可执行；脱敏/日志留存/合规边界完整 |
| 12–16 | 架构图清晰；白名单与出域有说明，离线方案停留在「可以」层面 |
| 7–11 | 有适配分析但泛泛而谈（套话多、无具体配置/流程） |
| 0–6 | 无架构图，或适配分析缺失/照抄模板 |

## 三、评分流程（群主操作，约 30–40 分钟/人）

1. **收作业**：学员提交后，将其交付物归档到 `capstone/submissions/<姓名>/`
2. **跑系统**：按学员「运行说明」复现启动；跑不动先记「功能 ≤10」，再尝试按 README/代码救活
3. **实测 12+3 题**：官方 10 题 QA + 抽 2 题 + 3 个异常 case，逐题记录（可直接在 SUBMISSION.md 自评表旁标注实测结果）
4. **打分**：按锚点给 5 个维度分，先算总分、再核对两条硬闸（总分 ≥70、环境适配 ≥12）
5. **记台账**：写入 `capstone/results.json`（格式见下），结论为「通过」才进入发证
6. **发证**：`python certs/generator.py --name "<姓名>" --tier intermediate --score <测验分> --capstone-score <capstone总分> --emit-html`
   （generator 会自动校验台账，未通过无法签发）
7. **通知**：把证书 HTML + 评语发给学员；不通过的给具体改进清单，允许 1 次补交重评

## 附录：官方 10 题 QA 实测集

> 评审时使用 rag_demo 内置的脱敏样例标书。学员自研系统的，先让学员把样例标书导入其系统再测。

| # | 问题 | 考察点 |
|---|------|--------|
| 1 | 本项目的预算金额是多少？ | 数值抽取 |
| 2 | 投标截止日期是哪一天？ | 时间抽取 |
| 3 | 投标人需要满足哪些资质要求？ | 列表类多要点 |
| 4 | 项目工期要求是多久？ | 数值+单位 |
| 5 | 投标保证金是多少，如何缴纳？ | 跨段落组合信息 |
| 6 | 评分办法里技术分占多少？ | 表格/结构化信息 |
| 7 | 中标后合同期限是几年？ | 细节事实 |
| 8 | 投标人可以联合体投标吗？ | 是/否 + 条件 |
| 9 | 交付地点在哪里？ | 地点事实 |
| 10 | 本项目是否接受外资参与？ | 标书未明确提及 → 考察拒答边界 |

> 第 10 题是**陷阱题**：样例标书未明确提及外资条款，正确答案是「标书未明确」而非编造。
> 答出「未明确提及」记 1 题对；编造「接受/不接受」记 0 并影响异常兜底维度。
