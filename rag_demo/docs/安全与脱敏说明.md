# 招标文件问答助手 · 安全与脱敏说明

> 适用对象：交付负责人、合规、使用方
> 核心立场：**招投标数据属敏感信息，真实场景须受控；本 Demo 默认使用虚构样本，可安全演示。**

---

## 一、数据敏感性认知

招标文件包含：预算金额、供应商资质门槛、评分权重、付款条件、项目时间表等，在真实业务中是**高敏感、常涉商业秘密甚至涉密**的信息。一旦泄露，可能造成：

- 投标方串标、围标风险；
- 商务策略与底价暴露；
- 合规与审计责任。

因此，**真实标书严禁随意上传、外传、截屏、入公开库**。

---

## 二、本 Demo 的脱敏现状（为什么能直接演示）

`data/` 下 3 个标书均为**虚构仿真样本**：

- 文末自带声明："本文件为测试用仿真样本，数据均为虚构，不代表任何真实采购活动。"；
- 全文统一使用"**某单位**"代指一切主体，无真实单位名、人名、金额、时间；
- 生成的索引 `index/` 同样不含任何真实信息。

→ **当前工程可安全用于教学、公众号、公开演示，无泄密风险。**

---

## 三、脱敏规范（红线，必须遵守）

结合项目既有保密要求，统一执行：

| 场景 | 规则 |
|------|------|
| 真实单位 / 公司名 | 一律写作"**某单位**""**某公司**" |
| 真实人名、地名、项目代号 | 同样脱敏处理 |
| 公开商业品牌（DeepSeek、Kimi、Qwen、BGE-M3 等） | **豁免**，可直书（属公开技术信息） |
| 对外文档 / 文章 / 演示 | 提交前二次检查，确保无真实主体泄露 |

> 原则：**凡能定位到具体组织/个人的，都脱敏；纯行业技术信息，可直书。**

---

## 四、数据不出域与 API 调用边界（重要）

本 Demo 在**本地运行**，标书 PDF 和 FAISS 索引**不会上传到任何第三方存储**。

但需注意一个边界：**调用模型 API 时，问题文本与召回的标书原文片段会作为请求体发送给 ModelScope / Jina**。

- 当前用的是**虚构样本**，无影响；
- **真实标书接入时**，这意味着原文片段会"出域"到第三方大模型服务——必须：
  1. 确认第三方服务商有**数据合规承诺 / 私有化部署选项**；
  2. 或改用**本地私有模型**（本地 Embedding / Rerank / Chat），做到真正不出域；
  3. 或先对原文做**脱敏替换**再送入 API。

---

## 五、密钥管理

- `MODELSCOPE_API_KEY`、`JINA_API_KEY` 存于 `.env`，已加入 `.gitignore`，**不入库、不截图外传**；
- 部署机上 `.env` 权限设为 `600`；
- 令牌按环境区分、定期轮换、最小权限。

---

## 六、人工复核与责任边界

- AI 输出**仅供参考**，不构成投标或法律意见；
- 所有关键条款（预算、资质、截止时间、评分、付款）**须以招标文件正式文本为准**，并经人工复核；
- 建议在 UI 显著位置保留免责声明（本 Demo 已在 README 与《用户操作手册》中体现）。

---
