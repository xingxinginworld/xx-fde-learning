# 招标文件问答助手 · 部署运维手册

> 适用对象：运维人员、接手开发、FDE 交付自检
> 目标：从"本地能跑"到"服务器上稳跑、能更新、能排障"。

---

## 一、环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | Windows / Linux / macOS |
| Python | **3.13**（依赖已锁版本，建议用虚拟环境） |
| 内存 | ≥ 2 GB（FAISS 索引 + Streamlit 常驻） |
| 网络 | 需能访问 `api-inference.modelscope.cn` 与 `api.jina.ai`（调用模型 API） |
| 密钥 | `MODELSCOPE_API_KEY`（必填）、`JINA_API_KEY`（建议，启用重排） |

---

## 二、本地一键启动（开发 / 演示）

```bash
# Windows：双击 run.bat
# Linux / Mac：
bash run.sh
```

脚本自动完成：建 `.venv` → 装依赖 → 首次建索引 → 起 Streamlit（默认 `http://localhost:8501`）。

> 若已手动建过索引，脚本会跳过重建，直接起服务。

## 三、Linux 服务器部署（生产 / 驻场）

### 3.1 部署步骤

```bash
# 1. 上传工程到服务器（含 data/ 下的标书）
# 2. 进入目录，建虚拟环境
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 3. 配置密钥
cp .env.template .env
vi .env   # 填入 MODELSCOPE_API_KEY、JINA_API_KEY

# 4. 构建索引（一次性，离线跑）
.venv/bin/python build_index.py

# 5. 后台常驻启动
nohup .venv/bin/streamlit run app.py \
  --server.port 8501 --server.address 0.0.0.0 \
  > streamlit.log 2>&1 &
```

### 3.2 用 systemd 托管（推荐，开机自启 + 崩溃重启）

`/etc/systemd/system/ragdemo.service`：

```ini
[Unit]
Description=RAG Demo (招标文件问答助手)
After=network.target

[Service]
WorkingDirectory=/opt/rag_demo
ExecStart=/opt/rag_demo/.venv/bin/streamlit run app.py --server.port 8501
Restart=on-failure
User=appuser
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ragdemo
sudo systemctl status ragdemo
```

### 3.3 反向代理（可选，暴露域名 / HTTPS）

用 Nginx 反代 `http://127.0.0.1:8501`，并配置 `streamlit config` 的 `allowedOrigins`。涉及公网务必加鉴权，避免标书内容裸奔。

## 四、Docker 化（可选）

`Dockerfile`（示例）：

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
# 索引需在容器内构建（或挂载已建好的 index/）
RUN python build_index.py
EXPOSE 8501
CMD ["streamlit", "run", "app.py", "--server.address", "0.0.0.0"]
```

```bash
docker build -t ragdemo .
docker run -d -p 8501:8501 --env-file .env ragdemo
```

> 注意：容器内的 `index/` 与 `data/` 建议用 volume 挂载，避免重建镜像丢失索引或标书。

## 五、索引更新流程（加新标书怎么办）

RAG 的知识来自 `data/` 下的 PDF，索引与代码**分离**，更新标书只需重建索引：

```bash
# 1. 把新标书放进 data/（如 tender_zb2026_004.pdf）
# 2. 重建索引（会覆盖 index/vecs.faiss 与 chunks.json）
.venv/bin/python build_index.py
# 3. 重启服务（若用 systemd）
sudo systemctl restart ragdemo
```

- 增量更新暂未实现，**全量重建**即可（标书量级小，秒级完成）。
- 若只删/改个别文件，同样全量重建，保证索引与 `data/` 一致。

## 七、常见故障排查（FDE 踩坑固化）

| 现象 | 根因 | 解决 |
|------|------|------|
| `TypeError: ... unexpected keyword argument 'proxies'` | 全局 `openai==1.40` + `httpx==0.28` 不兼容 | **必须用本项目 `.venv`**（`requirements.txt` 已锁 `httpx==0.27.2`）；不要全局 `pip install` |
| `API key 为空 / 401` | `.env` 未填或 `config.py` 未 `load_dotenv` | 确认 `.env` 存在且 `MODELSCOPE_API_KEY` 已填；`config.py` 已内置 `load_dotenv` |
| `faiss.write_index ... No such file or directory` | faiss C++ 层不支持中文路径（如 `AI项目经理成长`） | 已改用 `serialize_index` + Python 字节读写绕过，正常情况下不会再现 |
| 重排失败、回退向量排序 | Jina 接口偶发网络抖动 | 正常兜底，主流程不受影响；频繁则检查网络 / 换 `RERANK_PROVIDER=dashscope` 或 `none` |
| 页面白屏 / 起不来 | 索引未构建或 `index/` 缺失 | 先跑 `build_index.py`；`app.py` 已加索引缺失的友好提示 |
| 召回不到相关内容 | 阈值过高 / 分块不合适 | 调低 `SIM_THRESHOLD`、增大 `CHUNK_OVERLAP`，或重建索引 |

## 八、密钥管理

- `.env` **不入库**（` .gitignore` 已忽略），仅存于部署机。
- 密钥用**最小权限**令牌，定期轮换。
- 多环境（开发/生产）用不同令牌，避免一损俱损。
- 服务器上 `.env` 权限设为 `600`，仅运行用户可读。
