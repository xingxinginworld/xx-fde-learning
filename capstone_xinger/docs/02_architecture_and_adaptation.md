## 一、系统架构

### 1.1 总体数据流

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          离线阶段（一次）                                │
│                                                                         │
│  data/*.pdf ──▶ build_index.py ──▶ index/vecs.faiss（FAISS 向量库）     │
│  (脱敏标书)      pdfplumber 抽文本      index/chunks.json（原文块+元数据）│
│                   分块500字/重叠80     （text/page/source/min_role）     │
│                   Qwen3-Embedding-0.6B 向量化 + L2 归一化                │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                          在线阶段（每次提问）                             │
│                                                                         │
│  用户问题                                                                │
│     │  入口A: Streamlit (app.py)   入口B: CLI (ask.py --role public)    │
│     ▼                                                                    │
│  ① embed() ── Qwen3-Embedding-0.6B（魔搭 API，OpenAI 兼容协议）          │
│     ▼                                                                    │
│  ② FAISS IndexFlatIP 粗筛 ── 召回 COARSE_K=20 候选（内积=余弦）          │
│     ▼                                                                    │
│  ③ 双重过滤 ── 相似度 ≥ SIM_THRESHOLD(0.4)  ∧  角色权限 min_role ≤ role  │
│     │     全被过滤 → 返回空 → 明确拒答话术（L1/L2 兜底）                 │
│     ▼                                                                    │
│  ④ rerank() ── Jina reranker 精排 Top-5                                 │
│     │     失败 → 自动回退向量粗排（L4 兜底，实测 24.4s→2.8s）            │
│     ▼                                                                    │
│  ⑤ generate() ── Qwen3-8B 强制 JSON（enable_thinking=False）            │
│     │     system prompt 五条硬规矩：只用资料/没写就说未提及/            │
│     │     标出处/金额日期一字不改/严格 JSON                              │
│     ▼                                                                    │
│  ⑥ 输出 {answer, citations[来源+页码], confidence}                      │
│     │     异常 → logs/ask_error.log（结构化，不含密钥）                  │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 模块职责（文件级）

| 文件 | 职责 | 关键设计 |
|------|------|----------|
| `config.py` | 全局配置中心 | 所有参数外置到环境变量，换模型/调阈值不改业务代码 |
| `model_client.py` | 模型调用封装 | 3 个函数 embed/rerank/chat_json；rerank 多供应商可切；绝不写死 Key |
| `retriever.py` | 检索链路 | 阈值+权限双过滤；rerank 失败自动降级向量粗排 |
| `generator.py` | 生成链路 | system prompt 行为边界 + 强制 JSON + 生成失败兜底 |
| `ask.py` | CLI 入口 | 分段计时、空检索拒答、异常落盘、`--role` 权限入口 |
| `app.py` | Streamlit 入口 | 交互界面，与 CLI 并存（评审可任选其一复现） |
| `build_index.py` | 离线建索引 | 扫描 data/*.pdf，产物落 index/ |
| `eval_demo.py` | 效果评测 | 13 题固化基线，产物 eval_result.json |
| `md2docx.py` | 报告导出 | 答案转 docx 交付 |

### 1.3 外部依赖（网络出口面）

| 依赖 | 地址 | 用途 | 是否必须 |
|------|------|------|----------|
| 魔搭 ModelScope | `api-inference.modelscope.cn:443` | Embedding + 生成 | **必须**（唯一核心依赖） |
| Jina | `api.jina.ai:443` | Rerank 精排 | 可选（可切 dashscope 或 none 降级） |

## 二、政企环境适配分析（白名单 / 离线 / 合规）

### 2.1 出域边界（数据往哪去）

| 数据 | 出域行为 | 边界说明 |
|------|----------|----------|
| 标书原文（离线） | **不出域** | PDF 解析、分块、向量化均在本地完成；向量库与原文块留在 `index/` 本地磁盘 |
| 标书分块文本（在线） | **出域** | 提问时仅把问题向量（非原文）发给魔搭做 embed；rerank 时会把**候选段落原文**（≤20 段）发给 rerank 服务 |
| 生成 prompt（在线） | **出域** | 问题 + Top-5 段落原文拼进 prompt 发给魔搭 chat 接口 |

**结论与整改**：当前默认配置下，**标书原文会出域**（rerank + 生成两处）。政企涉密场景不可接受，整改路径见 2.3 私有化方案。非涉密场景（如本次学习演练的脱敏标书）可接受，且已把出域面收敛到 2 个域名、2 个端口（均 443）。

### 2.2 白名单与端口（逐项）

**防火墙出方向白名单（最小化配置）**：

```
# 必须
api-inference.modelscope.cn   443/tcp   # Embedding + 生成
# 可选（启用 rerank 时才开）
api.jina.ai                   443/tcp   # Jina 精排（境外服务，见 2.3 建议替换）
# 若切阿里百炼 rerank
dashscope.aliyuncs.com        443/tcp
```

- 入方向：仅 Streamlit 服务端口 `8501`（对内网/堡垒机开放，不暴露公网）；CLI 形态则**零入方向端口**。
- DNS：上述 3 个域名（建议政企内网 DNS 加 A 记录固定解析，防劫持/防解析漂移）。
- 其他：系统不访问任何未列明域名；`requirements.txt` 全部依赖走内网 PyPI 镜像安装（一次性）。

### 2.3 离线 / 私有化部署方案（可执行级别）

**核心原则：把 2 个公网依赖逐个换成内网自部署模型，业务代码零改动（得益于 config 参数外置）。**

| 公网依赖 | 私有化替换 | 操作 |
|----------|------------|------|
| 魔搭 Embedding（Qwen3-Embedding-0.6B） | vLLM / TEI 内网部署同名开源模型 | `MODELSCOPE_BASE_URL` 指向内网 vLLM 的 `/v1`（OpenAI 兼容），`API_KEY` 填内网网关的任意 token |
| 魔搭 Chat（Qwen3-8B） | 内网 GPU 服务器 vLLM 部署 Qwen3-8B | 同上，`CHAT_MODEL` 保持 `Qwen/Qwen3-8B` |
| Jina Rerank | ① 切 `RERANK_PROVIDER=none` 直接去掉该依赖（**本次已实测可用，答案无回退**）；② 或内网部署 bge-reranker-v2-m3，切 `RERANK_PROVIDER=dashscope` 并改 `DASHSCOPE_RERANK_URL` 指向内网网关（接口同为 /v1/rerank 兼容格式） | 改 2 个环境变量，不动代码 |
| ModelScope 本身（若整体隔离） | 全链路走内网 vLLM 网关，统一 OpenAI 兼容协议 | 一个 base_url + 一个 key |

**私有化后的出域边界**：**零出域**。标书原文、向量、prompt 全部留在内网；唯一残留是模型本身（开源权重内网部署，可审计）。

**硬件参考**（单节点）：Qwen3-8B（BF16）约 16GB 显存 + Embedding 0.6B 约 2GB → 一张 A10/24G 或 2 张 T4 即可承载本 demo 规模（3 份标书、单用户）。规模放大时按 Qwen3-8B INT4 量化 + 多副本 + 请求队列扩展。

### 2.4 脱敏 / 日志留存 / 合规边界

| 项 | 现状 | 说明 |
|----|------|------|
| 数据脱敏 | ✅ 已完成 | 3 份标书均为脱敏样例（「某单位采购中心」），全文无真实单位/公司/人名；`data/` 随仓库提交可全文复查 |
| 密钥管理 | ✅ | 密钥全部在 `.env`（已 gitignore，不入仓库）；代码零硬编码；日志不含密钥（`ask.py` 只记异常类型+截断详情） |
| 日志留存 | ✅ | `logs/ask_error.log` 结构化（时间戳/级别/问题摘要/异常类型），可审计回溯；留存周期建议 ≥ 6 个月 |
| 权限控制 | ✅ | 块级 `min_role` 元数据 + 检索期角色过滤，越权内容不召回、不进入生成 prompt |
| 拒答边界 | ✅ | 检索为空明确拒答不编造；未提及事实回答「文档中未提及」 |
| 合规声明 | ✅ | 系统定位为学习演练，正式招投标须人工复核（已写入验收文档与提交单） |
| 已知合规风险 | ⚠️ 已披露 | 默认配置的 rerank 依赖**境外** Jina 服务——政企环境**禁止**使用，必须按 2.3 切 none/dashscope 或内网 reranker。此为如实披露项，不影响脱敏数据的本次演练 |

## 三、一页结论

1. 架构为「离线建索引 + 在线检索生成」标准 RAG，模块职责单一、参数全部外置；
2. 出域面收敛到 2 域名 1 端口（443），CLI 形态零入方向；
3. 私有化路径可执行：改 3 个环境变量即可全链路内网化、零出域，无需改业务代码；
4. 脱敏/密钥/日志/权限/拒答五项合规控制全部落地并有代码可查；
5. 唯一已知风险（Jina 境外依赖）已如实披露并给出可执行替换方案（本次实测 `none` 降级答案无回退）。
