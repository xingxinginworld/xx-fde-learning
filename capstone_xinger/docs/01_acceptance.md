> 所有数据均来自本次提交的真实运行产物（`eval_result.json` + 实测命令输出），非估算。

## 一、功能验收（能不能答）

**验收标准**：检索→生成闭环完整；预算/截止日/资质/评标权重等核心问法全部可答；支持多角色（权限分级）调用。

| 验收项 | 标准 | 实测结果 |
|--------|------|----------|
| 检索→生成闭环 | 任意问题走完 embed→FAISS 粗筛→阈值过滤→权限过滤→rerank→生成→JSON 答案 | ✅ 13/13 题走完整链路（`eval_demo.py`） |
| 预算类问法 | 金额准确 + 引用出处 | ✅ 「伍佰捌拾万元整（¥5,800,000.00）」，引用 tender_zb2026_001.pdf 第1页 |
| 截止日问法 | 日期准确 | ✅ 「2026年7月15日09时30分」 |
| 资质类问法 | 多要点齐全 | ✅ 「安全生产许可及 ITSS 运维资质」 |
| 评标办法/权重 | 结构化数据准确 | ✅ 「综合评分法：报价30/技术50/商务20」 |
| 跨文档问法 | 能汇总多个文档信息 | ✅ 三项目名称+编号一次列全，引用 3 个来源 |
| 多角色调用 | `--role public/staff/manager/admin` 按权限召回 | ✅ CLI 支持，retriever 按块级 `min_role` 过滤 |
| 双入口 | Streamlit 界面 + CLI 均可独立运行 | ✅ `streamlit run app.py` / `python ask.py "问题"` |

**复现命令**：

```bash
RERANK_PROVIDER=none .venv/Scripts/python.exe eval_demo.py   # 跑 13 题验收集
RERANK_PROVIDER=none .venv/Scripts/python.exe ask.py "ZB2026-001 项目的预算是多少？" --role public
```

## 二、效果验收（答得准不准）

**验收标准**：自构造 QA 集（对齐官方 10 题考察点，共 13 题）实测准确率 ≥ 90%，事实题答案均附原文引用（文件+页码可回溯）。

**实测结果（`eval_result.json`，真实产物）**：

| 指标 | 标准 | 实测 |
|------|------|------|
| 总题数 | ≥ 10 | **13**（11 事实 + 1 跨文档 + 1 未提及陷阱） |
| 检索命中率（事实题） | ≥ 80% | **100%**（11/11） |
| 答案事实准确率 | ≥ 90% | **100%**（13/13） |
| 引用来源 | 每答可回溯 | 12 题附引用；未提及题按规矩不附 |
| 置信度分布 | — | high 12 / low 1（low 为未提及题，符合预期） |
| Bad case | 0 | **0** |

**覆盖官方考察点对照**：

| 官方考察点 | 对应题 | 结果 |
|------------|--------|------|
| 数值抽取（预算） | 题1 | ✅ |
| 时间抽取（截止日） | 题2 | ✅ |
| 列表类多要点（资质） | 题10 | ✅ |
| 数值+单位（服务期/质保期） | 题7/11 | ✅ |
| 表格/结构化（评标权重） | 题6 | ✅ |
| 是/否+条件（联合体） | 题5 | ✅ |
| 跨段落组合 | 题12（跨文档） | ✅ |
| 拒答边界（未提及） | 题13 | ✅ 回答「文档中未提及」，置信度 low |

> 题13 即官方第 10 题陷阱的同类：标书未写「项目经理资格证书」，系统答「文档中未提及」而非编造。

## 三、性能验收（快不快、稳不稳）

**验收标准**：单次响应 P50 ≤ 5s（含生成）；分段耗时可观测；关键参数可调。

**实测延迟（5 题，`RERANK_PROVIDER=none` 降级模式，含 embed+FAISS+生成）**：

| 问题 | 检索段 | 总耗时 |
|------|--------|--------|
| 预算金额 | 0.7s | 2.6s |
| 评标办法权重 | 0.5s | 2.6s |
| 服务期 | 0.5s | 2.3s |
| 投标截止日 | 0.7s | 2.6s |
| 检索为空拒答 | 0.5s | 0.5s（不进生成） |

- **P50 总耗时 ≈ 2.6s ≤ 5s 达标**；瓶颈在生成段（约 2s），检索段 ≤ 0.7s。
- 分段计时内建于 `ask.py`（每次调用打印「检索 X s | 总计 X s」），延迟剖析可复现。
- 性能调优手段已具备并实测：
  - `TOP_K`（默认 5）：控制送生成模型的段落数，直接控制生成 token 量；
  - `COARSE_K`（默认 20）：粗筛召回量，控制 rerank 请求体大小；
  - `RERANK_PROVIDER=none`：rerank 依赖不可用时自动降级，实测 24.4s → 2.8s（见 03_bad_cases.md 案例1）；
  - 索引内存常驻（`faiss.deserialize_index` 只加载一次），无重复 IO。
- 并发说明：本 demo 为单用户 CLI/界面形态，FAISS 检索段本身是毫秒级、可并发；生成段为同步 API 调用，政企正式部署时建议加请求队列（见 02 文档部署建议）。

## 四、异常验收（不会的敢不敢说不会）

**验收标准**：未提及问题不编造；模糊问题不硬答；脏输入不崩溃；异常有日志可查。

**3 个刁钻 case 实测（真实命令输出）**：

| # | 输入 | 系统表现 |
|---|------|----------|
| ① | 「本项目是否接受外资参与投标？」（标书未提及） | ✅ 检索层拦截：「未在知识库中检索到相关内容」+ 3 条排查建议，0.5s，不进生成、不编造 |
| ② | 「那个东西多少钱」（语义模糊） | ✅ 同上，检索为空走兜底话术，不硬编 |
| ③ | `@@@@##$$%^&*asdfghjkl`（乱码脏输入） | ✅ 同上，不崩溃、无堆栈外露，友好提示后正常退出 |

**兜底分层设计（代码可查）**：

| 层 | 位置 | 行为 |
|----|------|------|
| L1 检索兜底 | `retriever.retrieve()` | 无块过阈值/全被权限过滤 → 返回空 |
| L2 话术兜底 | `ask.py` | 空结果 → 明确拒答 + 建议（换问法/查范围/查索引） |
| L3 生成兜底 | `generator.generate()` | 模型调用异常 → 返回「⚠️ 生成失败」+ confidence=low，界面不崩 |
| L4 重排兜底 | `retriever.retrieve()` | rerank 超时/不可用 → 自动回退向量粗排，主流程不中断 |
| L5 日志兜底 | `ask.py` → `logs/ask_error.log` | 结构化记录（时间/级别/问题摘要/异常类型/截断详情），**不含任何密钥** |

## 五、灰度验收（能不能安全上线）

**验收标准**：可分批放量、可回滚、可观测、有一键开关。

| 灰度手段 | 实现 | 说明 |
|----------|------|------|
| 权限分级放量 | `--role` 四级角色 + 块级 `min_role` 元数据 | 先只对 admin/staff 开放内测，验证后放开 public，**无需改代码**，靠数据层权限位控制 |
| 功能开关 | `RERANK_PROVIDER` 环境变量（jina/dashscope/none） | 精排服务异常时一条命令降级为纯向量检索，实测可用（案例1） |
| 参数热调 | `TOP_K`/`COARSE_K`/`SIM_THRESHOLD` 全走环境变量 | 灰度期按 bad case 反馈调阈值（如误召回多则上调 threshold），不发布代码 |
| 评测基线 | `eval_demo.py` + `eval_result.json` 固化 13 题基线 | 每次改动后重跑，准确率/命中率不回退才允许放量（本次基线：13/13、100%） |
| 日志观测 | `logs/ask_error.log` | 放量期间盯异常率；日志结构化、可 grep、不含密钥 |
| 回滚 | 系统无状态（索引在 `index/`，重建只需 `build_index.py` 一条命令） | 出问题直接停服回滚旧版索引，数据不丢失 |

**灰度节奏建议**（提交人自评）：
1. 第 1 周：仅 admin 角色 + 群主内部 2 人，用官方 10 题集每日抽测；
2. 第 2 周：放开 staff，观察 `ask_error.log` 异常率 < 1% 再放；
3. 第 3 周：放开 public，保留 `RERANK_PROVIDER=none` 降级开关随时可用。
